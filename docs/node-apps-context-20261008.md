# Node.js 앱 관리 요청 문맥

기존 generation 검사는 늦은 응답만 차단했고 연결 교체 직후 저장 callback의 이전 API 호출은 막지 못했다. 컴파일된 화면에서 실제 callback을 보관해 API를 교체한 후 호출하는 실패를 재현했다. 요청 전에 현재 연결/정책/앱 선택 snapshot을 검사하며 effect 처리 전에도 이전 앱 정보를 숨긴다. 단일 진행 요청으로 중복 저장을 차단하고 다른 연결의 응답·오류가 현재 화면을 바꾸지 않게 했다.

서비스 등록 확인은 검토한 동일 plan에 한 번만 사용한다. 취소/설정 변경/조회/요청 이후에는 이전 확인을 재사용할 수 없다. 파일 편집 권한 변경은 보관된 저장 callback도 차단한다. 같은 내용의 보안 snapshot 객체 갱신은 미저장 편집을 초기화하지 않는다.

관련12개 검사에서 이전 연결/effect 이전 보호, 중복 저장, 늦은 응답, 권한 해제, 확인 소모, 같은 정책 편집 유지 및 정상 등록 설정/탭/상태 조회 동작을 확인했다. 최초 재현의 중복 요청 test가 해결하지 않는 Promise를 먼저 await하여 정지한 기록을 보존하고 확인 순서를 바로잡았다. 기존 등록 UI fixture는 확인 승인 ref 없이 state만 삽입했으므로 실제 등록 확인 버튼을 먼저 누르도록 변경했다. 서비스 동작을 모의하는 로컬 컴포넌트 검사이며 설치된 서비스의 실행을 증명하지 않는다. 증거: `.runtime/verification/node-apps-context-20261008/result.json`.

직전394개 소스 운영 빌드/HTTP 증거는 이 변경 이전이다. 이번 변경은 SWC 컴파일 및 관련 UI 검사로 확인했다. 호스트 서비스 변경·배포 검수는 수행하지 않았다.
