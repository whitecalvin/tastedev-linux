# 인증서 완료 작업 재시작 조회 — 2026-10-06

`operationJob`은 실행 중 메모리 기록을 우선 조회하며 해당 ID가 없으면 `server-tools/<UUID>.log.json` 완료 기록을 읽는다. 인증된 `admin-job` GET API는 비동기 조회 완료를 기다려 기록 또는 오류를 반환한다. 실제 인증서 발급을 다시 실행하지 않는다.

저장 기록은 UUID와 파일 내부 ID, 완료 상태, Certbot 명령 배열, 로그 수·길이, 종료 코드·시각을 확인한다. 파일과 부모 경로의 링크, 파일 소유자·권한·하드링크·크기 및 읽는 동안 변경 여부를 검사한다. 반환 필드를 제한하여 알 수 없는 필드는 제외한다. 기존 종료 시각·signal 없는 완료 기록도 읽을 수 있다. 손상되거나 실행 중 상태로 저장된 기록은 완료 결과로 반환하지 않는다.

## 확인

`admin-job-record.test.mjs`, `async-operation-audit.test.mjs`, `nginx-audit-api.test.mjs` 12개 통과. 완료 기록을 새 Node.js 프로세스의 실제 `operationJob`으로 읽어 재시작 조회를 확인했다. 제한 실행 환경의 최초 별도 프로세스 검사에서는 stdout이 반환되지 않아 실패했다. 별도 프로세스 실행 권한을 확보한 재실행에서 통과했다. 실제 Certbot 또는 운영 서비스 실행은 하지 않았다.

별도 `admin-job-api.test.mjs`와 비동기 작업·감사 API 검사 10개 통과. 비인증 조회는 기록 접근 전에 차단하고, 저장 조회 응답과 403/404/409 오류를 비동기 완료 후 반환함을 확인했다.

진행 중 앱 프로세스가 강제 종료된 경우 완료 여부를 추정하지 않는다. 기존 작업 잠금은 수동 확인 대상으로 보존되며 이번 변경은 완료 기록 조회만 복구한다. 운영 빌드·HTTP 증거는 이 변경 이전 소스다.
