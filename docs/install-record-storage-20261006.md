# 설치 작업 기록 저장 보완 (2026-10-06)

설치 작업 기록은 원래 디스크에 저장되어 있었다. 이번 변경은 새 영속화 기능이 아니라 비공개 저장 경로 및 읽기 검증 보완이다.

- 새 기록과 잠금은 `LINUX_AUTH_ROOT`가 지정되면 그 아래 `install-jobs`에 저장한다. 미지정 환경은 기존 state root 아래 별도 `install-jobs`를 사용하며 비공개 디렉터리 권한을 충족해야 저장된다.
- 저장은 private 임시 파일→fsync→rename→디렉터리 fsync 순서다. 기록 갱신은 기존 작업별 큐가 직렬화한다.
- 조회는 심볼릭 링크·하드 링크·파일 및 부모 권한·소유자·크기·읽기 도중 변경을 검사한다. UTF-8 JSON 및 설치 명령/상태/날짜/로그 구조도 검증하며 알려진 필드만 반환한다.
- 새 기록이 없으면 안전한 기존 `job.json`만 조회한다. 안전하지 않은 기존 파일은 사용하지 않으며 손상된 기존 JSON은 오류를 유지한다. 이전 `install.lock`이 남아 있으면 새 작업을 차단하여 저장 위치 변경으로 중복 설치가 시작되지 않도록 한다.
- 최대 로그 수에서 시간 초과 또는 spawn 오류가 추가되어도 최종 기록 한도를 넘지 않도록 보완했다.

검사: `node --test --test-isolation=none tests/install-job-record.test.mjs tests/async-operation-audit.test.mjs`, 10개 통과. 실제 파일 읽기/저장, 잘못된 권한·링크·JSON, 명령/상태 검증, 기존 잠금, 성공/실패/시간 초과 및 감사 저장 실패 흐름을 포함한다. 작업 child는 fixture다. 실제 apt 실행, 앱 재시작 HTTP 및 설치 운영 환경 수용 검사는 포함하지 않는다. 앞선 356개 소스 빌드는 이번 변경 이전 증거다.
