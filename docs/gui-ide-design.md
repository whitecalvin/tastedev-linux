# 패키지 관리 GUI IDE 설계 기준

2026-10-04. 사용자가 지정한 구조를 우선하며, 아래 참조는 상호작용 설계에 사용한다. VS Code 확장 개발 지침을 독립 서버 관리 웹앱의 API 요구로 해석하지 않는다.

## 참고 자료에서 가져올 원칙

- [VS Code UI 구조](https://code.visualstudio.com/api/ux-guidelines/overview): 기능군 선택, 탐색 목록, 편집 영역, 문맥별 작업의 역할을 분리한다.
- [VS Code Views](https://code.visualstudio.com/api/ux-guidelines/views): 트리는 대상을 탐색하는 곳이다. 노드 선택은 명령 실행이 아니며, 노드 작업은 작은 아이콘과 문맥 메뉴로 제공한다. 같은 기능을 여러 패널에 반복하지 않는다.
- [VS Code Settings](https://code.visualstudio.com/api/ux-guidelines/settings): 설정에는 값뿐 아니라 짧은 설명, 기본값, 복잡한 항목의 문서 링크를 제공한다.
- [nginx HTTP core](https://nginx.org/en/docs/http/ngx_http_core_module.html): 설정 이름·값·컨텍스트의 기준. nginx 검수 결과를 실제 적용 가능성의 기준으로 삼는다.

## 제품 구조

| 기능군 | 옆 목록 | 본문 |
| --- | --- | --- |
| 현황 | 대시보드·데몬·로그·복구·보안·감사 | 선택한 관리 화면 |
| 패키지 설치 | 없음 | 설치 후보 패키지 |
| 도구 | 설치된 패키지 | 패키지 전용 GUI IDE |
| 터미널 | 없음 | 나머지 영역 전체 터미널 |

nginx IDE는 고정 헤더 아래에 파일/블록 탐색 트리와 편집 영역을 둔다. 파일 경로와 블록 제목을 오른쪽에 다시 반복하지 않는다. 선택 상태는 트리에서 일관되게 강조한다. 헤더에는 실행 상태와 시작·종료·검수·백업·복원만 둔다. 검수·백업·복원은 별도 팝업이다. 하단 터미널과 상시 조회 전용 문구를 추가하지 않는다.

## 같은 설정의 두 표현

설정 GUI와 코드는 서로 독립적인 설정 데이터가 아니다. 하나의 파일 초안을 서로 다르게 표현한다.

1. 트리에서 파일/블록을 선택한다.
2. 설정 화면에는 선택된 컨텍스트의 항목을 표시한다. 같은 지시어가 반복되면 원래 순서와 반복을 유지한다.
3. 코드 화면은 파일 전체 또는 선택한 블록 범위만 편집한다.
4. 코드 반영은 파싱 후 초안 전체를 재생성한다. 트리와 설정 행은 다시 파싱한 순서로 갱신한다.
5. GUI 반영도 같은 파일 초안을 갱신한다. 코드 화면은 갱신된 초안을 읽는다.
6. 문법 오류와 오래된 편집 기반은 반영을 거부하고 편집 내용을 유지한다.
7. 운영 파일 적용은 초안 반영과 구분해 기존 검수·검토·적용 절차로 수행한다.

내용 비우기는 입력값만 비운다. 설정 이름/행 삭제와 혼동하지 않는다. 블록 삭제는 트리 문맥 메뉴의 별도 작업이다. 새 코드에 다른 노드가 끼어드는 블록 편집은 선택 범위가 모호해지므로 거부한다.

## 크기와 스크롤

오른쪽 컨테이너는 남은 폭·높이를 채운다. 설정/코드 전환은 위에 고정하고 콘텐츠만 독립적으로 스크롤한다. 트리는 오른쪽 스크롤에 따라 이동하지 않는다. 긴 트리의 자체 스크롤은 별도다. 카드 테두리와 중첩 바깥 여백 대신 패널 구분선을 사용한다. 공통 아이콘 버튼과 스위치의 크기·포커스·비활성 상태는 공유 컴포넌트에서 정의한다.

## 현재 소스와의 차이: 아직 끝나지 않은 일

- 기존 globals.css에 nginx 스타일이 여러 차례 덧붙어 있다. 기능별 스타일을 단일 정의로 정리해야 한다.
- 29개 주요 설정에 설명과 문서 링크를 추가했다. 확인한 일부 기본값도 제공한다. 전체 모듈 설정의 설명은 아직 부족하다.
- textarea 기반 편집에 줄 번호와 기본 nginx 구문 강조를 추가했다. 정확한 오류 위치와 브라우저에서의 편집 정렬 검증은 아직 남아 있다.
- 편집 버퍼와 선택은 파일/부모 블록/라벨/같은 라벨의 발생 순서를 사용한다. 서로 다른 앞선 노드의 추가를 검증했다. 동일 라벨 노드의 삽입·삭제 및 라벨 변경에서의 미반영 버퍼 복구는 추가 검토가 필요하다.
- 선택 경로로 현재 초안의 노드를 다시 조회하도록 변경했다. 전체 GUI 조작 중 선택 유지와 포커스는 실제 브라우저에서 확인해야 한다.
- 원문 편집과 GUI 편집에 동일한 변경 내역/상태 표현이 필요하다.
- 실제 화면에서 높이, 테마, 포커스, 좁은 화면, 팝업과 키보드 이동을 확인해야 한다. 빌드/컴포넌트 검사만으로 디자인 완료라 하지 않는다.

## 확인할 사용자 작업

- nginx.conf → http → server → location 선택 후 설정/코드가 같은 범위를 표시한다.
- 코드에서 지시어 순서를 변경하고 반영한 뒤 GUI 행과 트리가 그 순서를 따른다.
- GUI 값을 반영한 뒤 코드 화면에서 같은 값을 확인한다.
- 내용을 비우고 다시 입력해도 행/블록이 사라지지 않는다.
- 다른 노드/메뉴로 이동했다가 돌아와 미반영 코드를 확인한다.
- 운영 파일이 외부에서 바뀌면 이전 기반 편집으로 덮어쓰지 않는다.
- 긴 코드/설정에서 오른쪽만 스크롤하고 트리와 헤더는 고정된다.
- 시작·종료 후 실제 상태를 확인하고 검수 실패 로그·백업·복원을 각 팝업에서 처리한다.

이 문서는 설계 기준과 미완료 목록이다. 실제 기능/GUI 완료 증거를 대신하지 않는다.
