# MariaDB 실제 설정 적용·복구 확인 (2026-10-06)

한국어 기능 완성을 우선하며 추가 번역은 진행하지 않았다.

`scripts/verification/mariadb-lifecycle.mjs`를 추가했다. Ubuntu 저장소의 MariaDB 11.8.6 실행 파일을 임시 폴더에 추출하여 사용한다. 시스템에 패키지를 설치하지 않는다. 현재 계정이 소유한 임시 데이터 디렉터리와 Unix 소켓에서만 서버를 실행하며 TCP 연결을 비활성화한다.

현재 `applyMariaDBConfig`와 후보 설정 생성·native 옵션 검사·설정 트랜잭션을 실제 MariaDB 바이너리와 함께 실행했다. 내부 systemctl 어댑터는 임시 서버 프로세스만 종료·재시작한다. 운영 systemd나 권한 helper의 동작을 대신 증명하지 않는다.

확인 결과 5개 모두 통과했다.

- Unix 소켓 접속, TCP 비활성 및 초기 최대 연결 수 100 확인.
- 실제 후보 설정 검사 후 최대 연결 수 123 적용·재시작, 한글 행 유지.
- 생성된 파일 백업에서 전체 파일 복원 후 최대 연결 수 100 확인.
- MariaDB가 거부하는 잘못된 설정은 파일 교체 및 재시작 전에 차단.
- 실제 서버 기동 실패를 유발한 뒤 트랜잭션 원복·재기동, 이전 파일과 한글 데이터 유지.

증거: `.runtime/verification/mariadb-native-lifecycle-20261006/result.json`. 실행 파일 SHA-256, 실제 버전, 재시작 횟수 및 정리 결과를 기록했다. 자체 서버 종료와 임시 데이터 삭제를 확인했다. 기존 사용자 DB, host MariaDB 서비스 및 sudo 정책은 변경하지 않았다.

남은 범위: 설치 계정의 권한 helper·격리 검수, 실제 GUI→API→helper 전체 변경·실패·복구, 데이터베이스 내용 백업/복원. 이번 검사는 설정 파일 백업/복원에 한정한다. 최종 배포 패키지 검증은 실행하지 않았다.
