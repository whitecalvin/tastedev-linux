# 터미널 연결 전환 시 입력 요청

연결/API 교체 직후 화면의 입력 활성 여부는 즉시 false가 되지만, 이전 TerminalScreen이 가지고 있던 입력/크기 조정 콜백은 이전 API를 호출할 수 있었다. 컴파일된 TabbedTerminal 검사에서 콜백 두 개가 이전 연결로 추가 요청을 보내는 실패를 먼저 재현했다.

요청 직전에 연결 컨텍스트, 계정 조회 소유권, 현재 기능 허용 여부, 해당 세션의 running·PTY·stdinOpen 상태를 확인하도록 변경했다. 오래된 콜백이나 이미 종료된 셸 요청은 한국어 오류로 거부하고 API를 호출하지 않는다. 입력을 다른 셸로 재전송하지 않는다.

한글 조합 검사는 설치된 xterm의 CompositionHelper를 컴파일하여 수행하며 완성 글자 전송·받침 이동·Enter 순서·탭 전환을 포함한다. 실제 OS 입력기를 사용하는 브라우저/데스크톱 수용 검사와는 구분한다. 이번 수정은 컴파일된 컴포넌트와 입력 큐 회귀 검사로 확인했으며 실제 연결 교체 GUI 확인은 남아 있다.

## 도구 버튼 후속

보관된 새 탭·중지·닫기·설정 버튼 및 재연결 콜백도 연결 교체 뒤 이전 API로 요청을 보내는 실패를 재현했다(기대 3회, 실제 6회). 재현 검사 초기에는 응답 Promise를 기다려 자체 검사 프로세스가 대기했으므로 해당 두 프로세스만 종료하고, 호출 횟수를 먼저 검사하도록 바꾸어 FAIL을 확인했다.

시작·새 탭·중지·실행 중 탭 닫기·재연결은 현재 연결 및 계정 소유권/정책을 확인한다. 설정과 실행 기록의 오래된 콜백을 차단하며 다른 연결의 계정 정보는 설정 팝업에 표시하지 않는다. 종료된 기록의 로컬 닫기는 현재 화면에서 계속 가능하다. 정상 새 탭/셸 프리셋·종료·기록 선택·설정 조회와 관련 한글 입력 회귀 20개 통과. 실제 연결 교체 GUI 검사는 별도로 남아 있다.
