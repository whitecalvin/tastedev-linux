# nginx 복원 팝업 단일 흐름 — 2026-10-06

헤더 복원 팝업의 일반 백업/복원 API 선택 화면을 제거했다. 같은 팝업에 이미 있는 nginx 전용 백업 목록→복원 계획→include 연결 검토→검수/적용 흐름만 사용한다. 중단 작업 복구 패널은 유지한다.

기존 화면은 팝업을 열 때 일반 backups API를 추가로 호출하고 동일한 백업 선택과 영향 확인 화면을 두 번 제공했다. 이제 NginxBackupsPanel이 nginx-config-backups 및 nginx-config-restore-plan 요청을 담당한다. 이전 일반 restore 요청 경로는 헤더에서 제거됐다.

실제 JSX 컴파일 기반 헤더 검사와 기존 검수/복원 패널 검사 12개 통과. 헤더 복원을 눌러도 일반 backups 요청이 발생하지 않고 중복 선택/확인 UI가 없어지는지, 전용 패널에 연결/권한이 전달되는지 확인했다. 기존 늦은 응답 무효화, 중복 요청 차단, 복원 후 계획 정리/완료 안내/갱신 실패 구분도 통과했다.

현재 368개 소스 Next.js 빌드 /tmp/tastedev-current-build-tAFj2M 성공. 이 빌드의 별도 읽기 전용 임시 nginx GUI에서 복원 팝업을 열어 백업 선택 1개와 전용 복구 검토 버튼, 중단 작업 복구 패널을 확인했다. 기존 일반 복원 선택/영향 확인/버튼은 표시되지 않는다. 스크린샷 /tmp/tastedev-nginx-restore-popup-20261006.png. 임시 계정 로그아웃 후 로그인 페이지 이동과 임시 탭 종료를 확인했다. 실제 백업 생성/복원 실행 및 설치 환경 sudo/systemd 수용은 이번 검사에 포함하지 않는다. 운영 설정/서비스 변경 및 DEB 검증은 수행하지 않았다.
