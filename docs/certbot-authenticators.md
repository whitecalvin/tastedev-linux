# Certbot 인증 방식

Certbot GUI에서 인증서 발급 시 인증 방식을 선택합니다. 방식 또는 웹 루트 변경은 이전 명령 검토·실행 확인·약관 동의를 해제합니다. 새 명령을 검토하고 확인한 뒤 실행합니다. 기본값은 nginx입니다.

| 방식 | 동작 | 준비 조건 |
| --- | --- | --- |
| nginx | HTTP 검증 후 nginx HTTPS 설정과 리다이렉트를 연계합니다. | 이 앱이 관리하는 HTTP 사이트가 먼저 적용되어 있어야 합니다. 실행 전 사이트 설정을 백업합니다. |
| webroot | `certonly --webroot`로 기존 공개 웹 루트에서 HTTP 검증 파일을 제공합니다. | 해당 경로를 웹 서버에서 공개해야 합니다. 경로는 `/var/www`, `/srv`, `/opt`, `/usr/share/nginx` 중 하나의 아래에 있어야 합니다. 모든 상위 디렉터리와 기존 검증 디렉터리는 root 소유이고 다른 사용자가 쓸 수 없으며 심볼릭 링크가 아니어야 합니다. |
| standalone | `certonly --standalone`으로 HTTP 80 포트를 직접 사용합니다. | 80 포트를 사용할 수 있어야 합니다. 다른 웹 서버를 자동 종료하지 않습니다. |

webroot와 standalone은 nginx HTTPS 설정을 자동 수정하지 않습니다. 발급된 인증서의 HTTPS 설정 적용은 별도로 해야 합니다. 세 방식 모두 도메인의 DNS와 외부 HTTP 접근이 준비되어야 합니다. staging 테스트 인증서는 브라우저에서 신뢰하지 않습니다.

갱신 테스트는 기존 인증서의 갱신 설정을 사용합니다. GUI에서 선택한 새 발급 방식으로 갱신 플러그인을 바꾸지 않습니다. 기존 갱신 hook이 실행될 수 있습니다.

명령 검토와 관리자 helper는 동일한 검증된 명령 생성기를 사용합니다. 웹 루트 실제 디렉터리 권한은 관리자 helper가 실행 직전에 다시 검사합니다. 인증·CSRF·보안 설정·전용 관리자 helper 권한은 기존 실행 정책을 유지합니다.

지원하지 않는 범위: DNS 플러그인 인증 방식, 기존 갱신 파일의 인증 방식 변경, 실제 ACME 서버 발급의 자동 QA.
