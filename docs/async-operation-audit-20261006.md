# 비동기 설치·인증서 작업 감사 결과 — 2026-10-06

설치 및 Certbot API는 접수 시 `requested`만 기록하며 HTTP 202를 반환한다. 실제 자식 프로세스 종료 시 설치는 `install`, 인증서는 `certbot-issue` 작업명으로 `completed` 또는 `failed`를 기록한다. 요청 접수를 완료로 기록하지 않는다.

정책 차단은 실행 전 `blocked`, 시작 단계 오류와 설치 확인 누락은 `failed`를 기록한다. 명령 출력·요청 본문·예외 내용은 감사 이벤트로 전달하지 않는다. 종료 코드는 0이어도 실행 오류나 시간 초과가 있었다면 실패다. 종료 이벤트를 한 번만 처리하고 작업 종료 시각과 상태를 저장한다.

감사 기록 또는 작업 증거 저장 실패 시 잠금 파일을 보존하고 열린 파일 핸들은 닫는다. 일반 완료 시 잠금을 제거한다. 동기 실행 시작 오류는 실패 작업 기록을 저장하고 잠금을 해제한다. 실제 작업 성공 이후 감사 저장 실패는 작업 성공을 실패로 덮어쓰지 않으며 잠금을 통해 수동 확인을 요구한다.

## 확인

`node --test --test-isolation=none tests/async-operation-audit.test.mjs tests/nginx-audit-api.test.mjs tests/audit-log-page.test.mjs`: 12개 통과. 실제 소스 모듈을 컴파일하여 임시 파일과 자식 프로세스 이벤트 대역으로 성공·비정상 종료·실행 오류·시간 초과·중복 종료·감사 저장 실패·동기 시작 오류를 확인한다. 실제 apt 설치와 ACME 발급은 수행하지 않았다.

기존 `security.test.mjs`, `server-tools.test.mjs`는 임시 `LINUX_STATE_ROOT`, `LINUX_AUTH_ROOT`, `LINUX_WORKSPACE_ROOT`를 지정하여 59개 통과, 기존 독립 상태 필요 검사 1개 건너뜀. 최초 실행은 해당 임시 경로를 지정하지 않아 기본 인증 저장 경로 권한 검사에서 실패했다. 경로를 격리한 재실행에서 실패는 없었다. 기존 인증 경로 권한을 완화하지 않았다.

이 변경 이후 운영 빌드와 실제 설치 환경의 작업 종료 수용 검사는 아직 수행하지 않았다. 터미널 명령의 최종 감사 결과 연결은 별도 남은 항목이다.
