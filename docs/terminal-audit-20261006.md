# 터미널 종료 감사 기록 — 2026-10-06

터미널 시작 API는 요청 접수와 실행 시작 실패·정책 차단을 기록한다. 셸 종료 시 `terminal` 작업명으로 성공 `completed`, 실패 `failed`, 사용자가 중지한 작업 `cancelled`를 기록한다. 중지 요청 이후 실제 종료 이벤트에서만 최종 결과를 기록한다. 시간 초과는 중지 버튼이 나중에 눌려도 실패로 유지한다.

실행 오류와 시간 초과가 있었다면 종료 코드 0을 성공으로 해석하지 않는다. 종료 이벤트는 한 번 처리한다. 공개 작업 상태는 기존 `running/success/failed` 호환성을 유지하며 종료 시각과 `terminationReason`을 추가한다. 감사 저장 실패는 `auditError`로 표시하되 종료 상태 전달과 스트림 정리를 막지 않는다.

감사 파일에는 시각·작업명·결과만 저장하며 셸 명령과 출력은 포함하지 않는다. 셸 출력은 기존 터미널 기록에 그대로 유지한다. 감사 화면의 필터에 `cancelled`, `invalid`, `recovered`를 추가하고 기존 다국어 문구로 표시한다.

## 확인

- 관련 API/터미널/감사 UI 검사 8개 통과. 실제 소스를 컴파일하고 종료 이벤트 대역으로 시간 초과·실행 오류·중지·중복 종료·감사 저장 실패를 확인했다.
- 임시 상태·인증·작업 경로에서 기존 PTY/SSE/입력 큐/세션 검사 23개 통과. 실제 로컬 pipe 및 PTY의 한글·이모지 출력과 종료 전달을 포함한다.
- 별도 임시 경로의 실제 로컬 셸 성공, 종료 코드 7 실패, 실행 중 셸 중지를 검사했다. 생성된 감사 파일의 이벤트 필드와 결과를 확인하고 명령·출력 문자열이 포함되지 않음을 확인했다. `tests/terminal-audit-native.test.mjs` 1개 통과.

검증 중 생성된 셸과 임시 상태 경로는 정리했다. 운영 서비스나 sudo 정책은 변경하지 않았다. 네이티브 OS 입력기의 한영 전환·자모 조합 검사는 별도 미완료다.
