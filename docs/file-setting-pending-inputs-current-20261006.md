# 파일 설정 화면 미반영 입력 보존 — 2026-10-06

PostgreSQL·Redis·MariaDB 전체 파일 설정에서 검수 실패 입력이 Setting의 지역 상태에만 있어 탭 전환/행 재마운트 시 사라지고, 다른 파일의 동일 행에 지역 입력이 남을 수 있었다.

파일 코드 레코드의 pendingSettingInputs에 원본 행·입력·활성 상태·오류를 보관한다. 새 행 인스턴스는 해당 파일·원본 행과 일치하는 입력만 복원한다. 파일 경로를 행 key에 포함해 다른 파일의 동일 값/행에 이전 상태가 섞이지 않도록 했다. 한 항목 수정 성공 시 그 항목만 해제한다. 직접 코드 편집으로 원본 행이 달라졌을 때는 해당 미반영 입력을 제거하며, 무관한 행의 입력은 유지한다. 파서 자체가 실패하면 입력을 보존한다.

hasUnsavedIdeRecord와 파일 교체 확인은 미반영 입력도 변경으로 취급한다. 코드가 원본과 같고 다음 파일의 코드도 같은 경우에도 입력을 자동 폐기하지 않는다. 설정 검수를 완화하거나 잘못된 값을 운영 파일에 기록하지 않는다.

검사: 7개 관련 테스트 파일 17개 검사 통과. PostgreSQL·Redis·MariaDB의 원본 행 정합성, 다른 행 변경 시 보존, 행 변경/이동 시 정리, 컴파일된 설정 컴포넌트의 새 인스턴스 복원/다른 파일 격리/개별 수정, 미저장 감지 및 동일 내용 파일 교체 확인을 검사했다. 실제 브라우저 검사는 별도 기록한다. DEB 검사는 실행하지 않았다.

실제 GUI: 소스 367개 빌드 /tmp/tastedev-current-build-y1DaUr의 PostgreSQL 전체 파일 화면에서 port/max_connections에 닫히지 않은 따옴표를 입력했다. 코드 탭의 내용은 fixture 원본과 같고 설정 탭 복귀 시 두 입력이 유지되었다. port를 원래 값으로 수정해도 다른 입력은 유지되었다. 코드가 원본과 같은 상태에서 동일 내용의 다른 파일 선택 시 교체 확인이 표시되었으며 유지 선택 후 원래 파일의 입력이 복원되었다. 남은 입력을 수정한 후 로그아웃과 임시 탭/서버 정리를 완료했다. 운영 fixture 원본 불변 확인. 스크린샷 /tmp/tastedev-file-pending-inputs-20261006.png. 실제 브라우저 범위는 PostgreSQL이며 Redis/MariaDB 실제 GUI와 OS beforeunload 대화상자 검증으로 확대하지 않는다.
