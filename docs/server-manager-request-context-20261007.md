# 보조 설정 화면의 이전 연결 요청 차단

ServerManager의 API 래퍼가 응답 후 revision만 비교하던 구조를 보완했다. 이전 렌더에서 캡처한 API나 툴바 작업을 연결 교체 이후 호출하면 underlying transport를 실행하기 전에 거부한다. 연결 상태 자체가 false인 새 래퍼도 요청을 거부한다. 정상 연결의 초기 child 조회와 새로운 API의 조회는 유지한다.

같은 연결에서 시작했더라도 요청 완료 시 연결 객체와 revision을 모두 확인하므로 이전 결과를 현재 화면에 게시하지 않는다. perform의 시작 조건에도 렌더 당시 연결 객체 일치 검사를 추가했다. API 함수 변경과 connected 변경에 맞춰 래퍼가 다시 생성된다. API 경로, 인증서 방식, cron 내용과 실제 서버 실행 정책은 바꾸지 않았다.

관련 29개 검사 통과: 실제 JSX 컴파일 화면에서 effect 이전 이전 API/툴바 차단, transport 미호출, 이전 진행 응답 거부와 새 API 정상 조회; cron 반복 시간 왕복·요일/날짜 범위·퍼센트 입력 의미·환경 범위·관리 작업 편집/삭제·원본 보존; Certbot 명령/갱신 대상 및 보안 기능 제한 회귀. 실제 브라우저의 캡처된 이전 핸들러 수용·설치 서버 변경은 이번 범위에 포함하지 않는다.

기존 전체 검사 실패 중 이름 관련 항목은 재확인만 했다. tests/linux-branding.test.mjs의 legacy 입력 변환이 같은 문자열 치환이며, LINUX 포함을 동시에 요구/금지하는 모순이 남아 있다. 실제 helper linex-admin과 요청 linux-admin 파일 차이도 남는다. 이름 변경은 사용자 담당이므로 이 파일명/문자열을 대신 수정하지 않았다. 전체 runner를 불변 상태로 반복하지 않았으며 전체 성공이라고 보고하지 않는다.
