# 시스템 설정

`/settings`에서 기능별 옵션을 관리한다. 인증된 관리자만 접근하며 서버 설정 저장은 조회 전용 정책을 따른다.

- 로그: 최근 50·150·300·500·1,000줄, 자동 갱신 3·5·10·30·60초. 줄 수는 서비스·nginx 파일·등록한 Node.js 앱 조회 명령에 적용한다. 자동 갱신은 로그 화면의 스위치를 켰을 때만 실행한다.
- 터미널: 글꼴 크기, 커서 모양·깜빡임, 스크롤 기록, 새 셸 실행 시간. 기존 터미널 설정과 같은 상태를 사용하며 검증한 표시 설정과 실행 시간을 브라우저 로컬 저장소에 유지한다. 새로고침·로그아웃 뒤에도 유지하지만 셸 계정·명령·실행 세션·편집 중인 파일은 이 저장소에 기록하지 않는다.
- 보안: 기존 `/security`로 연결한다. 조회 전용, 기능별 변경 권한과 sudo 정책을 중복 구현하지 않는다.
- AI: 업체, API 방식·주소, 키, 모델, 처리 우선순위. 모델 갱신은 현재 키로 업체 API 목록을 조회하며 분석 요청은 별도 사용자 동의를 요구한다. 업체·주소를 바꾸면 기존 키를 전달하지 않는다. 키는 화면이나 API 응답에 재출력하지 않는다.

AI 키 저장 경로는 `LINUX_AI_SETTINGS_ROOT`, `LINUX_AUTH_ROOT`, `LINUX_STATE_ROOT` 순으로 선택한다. 선택한 경로 안 `ai-settings` 폴더 0700, 설정 파일 0600 권한을 요구한다. 로그 설정은 `LINUX_STATE_ROOT/system-settings.json`에 저장한다. 동시 저장 충돌은 409로 거부한다.

실제 로그 GUI에서 300줄 저장 후 150줄로 원복하고 재로딩 유지 확인. 문서 높이 720px, 뷰포트 720px, 설정 본문 높이 526px·스크롤 높이 1473px로 본문만 스크롤 확인. 실제 OpenAI 모델 목록 조회 성공은 분석 HTTP 429 해소를 의미하지 않는다. 타 업체 실계정 분석은 미검수이다.

후속 검수: 저장한 네 API 방식의 실제 로컬 HTTP 모델 갱신·한국어 분석 요청 8회에서 업체/모델/처리 우선순위/인증 헤더를 확인했다. 동의 전 및 설정 충돌 시 전송하지 않는다. 모델 갱신의 키 삭제 선택 재사용·설정 충돌·잘못된 JSON 원문 노출을 수정했다. 원래 설정 GUI에서도 키 삭제 초안 선택 후 갱신 시 키 입력 안내를 확인하고 선택을 원복했다. 실제 키를 삭제하거나 AI 설정을 저장하지 않았다. 외부 업체 분석 성공을 뜻하지 않는다. `.runtime/verification/ai-configured-http-20261009/result.json` 참조.

2026-10-09 09:01 KST: 기존 승인 키와 합성 nginx 오류만으로 실제 분석을 재확인했다. 여전히 업체 HTTP429, 상세 코드 없음. `.runtime/verification/ai-live-korean-2026-10-09T00-01-09.827Z/result.json` 참조. 모델 목록 조회 및 로컬 API 통합 성공을 실제 외부 분석 성공으로 취급하지 않는다. 사용자에게 설정 화면에서 사용 가능한 업체·모델·키를 등록하도록 요청했다.

AI는 기본 비활성화이며 기본 모델과 키를 지정하지 않는다. 개발 환경의 OPENAI_API_KEY·LINUX_ENABLE_AI·LINUX_AI_MODEL을 자동 사용하지 않는다. 사용자가 설정 화면에서 업체·모델·키를 등록하고 사용 스위치를 켜서 저장해야 분석할 수 있다. 비활성화 상태에서는 모델을 선택하지 않아도 저장할 수 있다.

AI 설정 화면의 처리 우선순위 항목은 제거하고 모델과 추론 수준을 함께 표시한다. GPT-6.1 Sol은 자동·Low·Medium·High·Extra High·Max 단계 슬라이더를 제공하며 저장한 수준을 Responses reasoning.effort 또는 Chat Completions reasoning_effort로 전달한다. 지원을 확인하지 않은 모델은 자동만 사용한다. AI는 계속 기본 비활성화다.

## 로컬 LLM

AI 업체에서 Ollama 또는 LM Studio를 선택한다. 각각 `http://127.0.0.1:11434/v1`, `http://127.0.0.1:1234/v1`을 자동 입력하고 OpenAI 호환 Chat Completions만 표시한다. 고급 연결 설정에서 포트를 변경할 수 있다. localhost는 웹 브라우저 장비가 아닌 이 앱 서버를 의미한다. 해당 서버에서 로컬 LLM API와 모델을 준비한 뒤 모델 목록 갱신 → 모델 선택 → AI 사용 켜기 → 저장 순서로 사용한다. 기본 비활성화 정책은 유지한다. API 키는 인증을 켠 로컬 서버에서만 필요하다. 모델 설치나 서버 기동을 자동으로 수행하지 않는다.

로컬 HTTP 통합 테스트에서는 키 없이 모델 목록과 한국어 합성 로그 분석이 전달됨을 검증한다. 실제 Ollama·LM Studio 설치 모델의 추론 성공과는 구분한다.
