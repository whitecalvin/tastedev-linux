# GitHub Next.js 빌드·배포 및 Webhooks

저장소 행의 실행 아이콘에서 **빌드 · 배포 / Webhooks** 작업창을 엽니다.
코드는 TASTEDEV LINUX가 설치된 서버의 일반 실행 계정으로 실행됩니다.

## 수동 작업

1. 브랜치, 프로젝트 하위 폴더(모노레포), 앱 포트, 환경 변수를 입력합니다.
2. 실행 내용을 확인한 뒤 빌드합니다. `npm ci --include=dev`와 저장소의 `npm run build`를 실행합니다.
3. 완료된 빌드를 선택해 배포합니다. 기존 Node.js 서비스 helper로 서비스 설치·변경·재시작 후 HTTP 응답과 서비스 상태를 확인합니다.
4. 외부 공개는 nginx 프록시로 별도 연결합니다. 앱은 `127.0.0.1`에서 실행됩니다.
5. 이전 빌드를 다시 선택해 배포할 수 있습니다. 배포 실패 시 자동 복구하지 않습니다. Node.js 서비스 관리 화면에서 로그·설정 백업·복구를 확인합니다.

지원 범위: npm package-lock.json과 Next.js 의존성 및 build 스크립트가 있는 서버 프로젝트.
정적 export, pnpm/yarn/bun, 임의 배포 스크립트, 별도 SSH 호스트는 현재 지원하지 않습니다.
앱 자동 시작은 Node.js 서비스 화면에서 별도 설정합니다.

## 권한과 보관

- 빌드: 조회 전용 해제, 웹 터미널 명령 실행(서버 환경 변수 포함), 작업 폴더 파일 저장 권한.
- 배포: 서비스 변경(서버 환경 변수 포함), sudo 비밀번호 생략과 helper 준비.
- 토큰: 해당 저장소의 Metadata 읽기·Contents 읽기. Webhook 자동 등록은 Webhooks 쓰기 권한 추가.
- 빌드는 저장소 코드와 npm 라이프사이클 스크립트를 실행합니다. 신뢰하는 저장소만 사용하세요. 별도의 컨테이너 격리는 제공하지 않습니다.
- GitHub 토큰은 git 가져오기 명령 환경에만 전달하고 npm 환경에 전달하지 않습니다. 환경 변수와 토큰 원문은 반환하지 않으며 일치하는 값은 로그에서 가립니다. 공개용 NEXT_PUBLIC 변수는 앱 빌드에 포함됩니다.
- 각 릴리스와 환경 변수는 상태 저장소의 github-deployments/jobs 아래 별도로 보존합니다. 최대 100개 기록, 동시 최대 2개, 저장소당 1개 작업입니다. 자동 삭제하지 않습니다.
- 관리 앱 재시작 시 진행 작업은 중단 상태로 표시합니다. 명령 감시 프로세스는 부모 연결 종료나 제한 시간 초과 시 명령 프로세스 그룹을 종료합니다. 재시작 후 재실행하세요.

## Webhooks

1. 빌드 설정과 공개 Webhook URL을 입력합니다. HTTPS를 권장합니다.
2. push 자동 빌드와 선택 사항인 빌드 성공 후 자동 배포를 켜고 확인 후 저장합니다. 두 옵션은 기본 꺼짐입니다.
3. 최초 저장 시 Secret을 한 번 제공합니다. 수동 등록은 GitHub 저장소 Settings → Webhooks에서 URL, application/json, Secret, push 이벤트를 설정합니다.
4. 또는 앱의 **GitHub에 Webhook 등록**을 누릅니다. 등록 성공 후 GitHub의 Recent Deliveries에서 ping·push 응답을 확인합니다.
5. 설정을 다시 저장할 때 환경 변수 값을 다시 입력합니다. 기존 비밀값은 화면에 재전송하지 않습니다.

수신은 원문 본문의 HMAC-SHA256을 상수 시간으로 비교합니다. 정확한 저장소와 브랜치의 push만 처리하며 태그·삭제 이벤트는 실행하지 않습니다. 최근 256개 전송 ID 중복을 차단하고 2MiB 본문 제한을 적용합니다. 수신 후 즉시 202 응답하고 빌드를 시작합니다. 전송 이력과 빌드 로그에서 결과를 확인합니다.
옵션을 끄면 서버 실행만 멈추며 GitHub에 등록된 Webhook은 자동 삭제하지 않습니다.

공식 서명 검증 문서: https://docs.github.com/en/webhooks/using-webhooks/validating-webhook-deliveries

## 저장소 프로젝트 종류

저장소 목록에서 기본 브랜치 루트의 프로젝트 파일을 확인해 Next.js, React, Vue, Node.js, Tauri, Rust, Python, Go 등 종류를 표시합니다. 여러 종류가 있는 저장소는 함께 표시하고 검색에도 반영합니다. 하위 폴더는 자동 탐색하지 않습니다. 비공개 저장소는 토큰의 Contents 읽기 권한이 필요합니다. 조회는 최대 3개씩 진행하고 결과는 저장소 업데이트 시각과 연결 정보별로 5분간 캐시합니다. 권한 또는 요청 제한으로 확인하지 못하면 미확인 상태로 표시하며, 저장소 조회나 빌드 버튼을 차단하지 않습니다.
