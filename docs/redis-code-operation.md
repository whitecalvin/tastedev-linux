# Redis 전체 코드 검수와 적용

`/ide/packages/redis`에서 main 파일을 선택한 뒤 설정 GUI 또는 코드 보기에서 편집합니다. 헤더의 검수 아이콘으로 별도 팝업을 열고 검수를 실행합니다.

검수는 원문 코드 전체와 include 파일을 private 후보에 복사해 기존 namespace/리소스 제한 환경에서 Redis 기동 검수를 수행합니다. 운영 파일과 운영 서비스는 변경하지 않습니다. 네이티브 Redis, 격리 도구 및 권한이 없으면 검수는 성공으로 표시하지 않습니다.

검수 이후 재시작 영향을 확인하고 검토한 설정 적용을 선택합니다. 적용은 현재 main 파일, 기존 include graph, 후보에 새로 포함되는 파일 graph와 정확한 코드가 검토 때와 일치하는지 검사합니다. 다시 기동 검수를 수행한 뒤 원본을 private 백업에 저장하고 파일을 교체·서비스 재시작합니다. 활성화 실패는 외부 편집을 덮어쓰지 않는 기존 복원/복구 절차를 사용합니다.

- readOnly가 꺼지고 databaseChanges·sudoWithoutPrompt·전용 helper 권한이 모두 허용돼야 합니다.
- 적용 가능한 대상은 `/etc/redis/redis.conf`입니다. 임의 경로·실행 명령·검수 runner를 요청으로 지정할 수 없습니다.
- 후보 기동 검수는 실제 외부 리소스와 데이터 지속성 정책의 운영 적합성을 보증하지 않습니다. 기존 리소스 분류와 제한을 유지합니다.
- 검수·적용 결과에는 암호나 native 원문 출력을 넣지 않습니다. 터미널에는 구조화한 상태와 백업 ID만 표시합니다.
- 팝업의 입력/연결/보안 설정이 바뀌면 이전 검토와 확인을 해제합니다. 늦은 응답과 중복 적용을 차단합니다.
- 실행 중단 기록이 있으면 새 적용을 진행하지 않습니다. 기존 Redis 중단 복구 화면에서 기록을 검토합니다.

파일 fixture·API·컴포넌트·rollback 검사와 실제 Redis native/설치 브라우저 E2E 검증은 별개입니다. 현재 개발 장비에는 `/usr/bin/redis-server`가 없어 이번 native 기동 검수 증거는 없습니다.
